# user-stories

## 1. 핵심 시나리오

**페르소나:** 박민준 — 개발자 (일반 직원), 칸반 툴 첫 사용  
**하루 흐름:** 출근(09:00) → 퇴근(18:00)

---

### 09:00 출근 직후 — 오늘 내 일감 파악

> **As a** 팀원,  
> **I want to** 담당자 필터에서 내 이름(박민준)을 선택해 내 일감만 보고 싶다,  
> **so that** 전체 팀 일감에 묻히지 않고 오늘 해야 할 일을 즉시 파악할 수 있다.

- 앱을 열면 칸반 보드 전체가 표시된다.
- 헤더의 담당자 드롭다운에서 "박민준"을 선택한다.
- "할 일" 컬럼에 내 일감 3건이 남고, 우선순위 배지(높음/중간/낮음)와 마감일을 훑어본다.

---

### 09:15 — 오늘 첫 번째 일감 착수

> **As a** 팀원,  
> **I want to** 우선순위가 "높음"인 일감을 "진행 중"으로 바꾸고 싶다,  
> **so that** 팀 리드와 동료가 내가 무엇을 하고 있는지 실시간으로 알 수 있다.

- "할 일" 컬럼의 카드에서 수정(연필) 버튼을 클릭한다.
- 상태를 "진행 중"으로 변경하고 저장한다.
- 카드가 "진행 중" 컬럼으로 이동하고 헤더 요약 수치가 갱신된다.

---

### 10:30 — 작업 중 요구사항 변경

> **As a** 팀원,  
> **I want to** 일감 설명(description)을 수정해 변경된 요구사항을 기록하고 싶다,  
> **so that** 나중에 다시 열었을 때 맥락을 잃지 않는다.

- 진행 중인 카드의 수정 버튼을 누른다.
- 설명란에 "디자인 팀 요청으로 버튼 색상 변경 추가"를 덧붙이고 저장한다.
- 카드 설명이 즉시 업데이트된다.

---

### 12:00 점심 전 — 진행 상황 간단 점검

> **As a** 팀원,  
> **I want to** 보드를 한눈에 훑어 진행 중인 일감이 정확한지 확인하고 싶다,  
> **so that** 오후에 무엇을 이어서 해야 할지 정리된 상태로 점심을 먹을 수 있다.

- 담당자 필터가 "박민준"으로 유지된 상태에서 세 컬럼을 빠르게 확인한다.
- "진행 중" 1건, "할 일" 2건임을 확인하고 앱을 닫는다.

---

### 13:30 오후 복귀 — 두 번째 일감 착수

> **As a** 팀원,  
> **I want to** "할 일" 컬럼의 두 번째 일감을 "진행 중"으로 옮기고 싶다,  
> **so that** 오후 작업을 시작했음을 팀에 알릴 수 있다.

- 오전과 동일하게 수정 다이얼로그에서 상태를 변경하고 저장한다.
- "진행 중" 컬럼에 카드가 2건으로 늘어난다.

---

### 15:00 — 첫 번째 일감 완료 처리

> **As a** 팀원,  
> **I want to** 작업이 끝난 일감을 "완료"로 변경하고 싶다,  
> **so that** 팀 리드가 완료 현황을 별도 확인 없이 파악할 수 있다.

- 완료된 일감 카드에서 수정 버튼을 눌러 상태를 "완료"로 변경한다.
- 카드가 "완료" 컬럼으로 이동하고 헤더 완료 수치가 올라간다.

---

### 16:00 — 팀 리드가 긴급 일감 배정

> **As a** 팀원,  
> **I want to** 새로 배정된 긴급 일감을 앱에서 즉시 확인하고 싶다,  
> **so that** 구두 전달 없이도 내 오늘 남은 우선순위를 재조정할 수 있다.

- 팀 리드가 앱에서 새 일감(우선순위 "높음", 담당자 "박민준", 마감 오늘)을 생성한다.
- 내가 담당자 필터를 새로 고침하면 "할 일" 컬럼에 새 카드가 보인다.
- 키워드 검색창에 일감 제목 일부를 입력해 빠르게 찾고 내용을 읽는다.

---

### 17:30 퇴근 전 — 일감 최종 점검

> **As a** 팀원,  
> **I want to** 내 이름으로 필터링해 남은 일감 수와 상태를 최종 확인하고 싶다,  
> **so that** 내일 출근 시 바로 이어서 작업할 수 있도록 현황을 정리해 둘 수 있다.

- 담당자 필터를 "박민준"으로 설정한다.
- "할 일" 1건(내일로 이월), "진행 중" 1건(내일 오전 마무리), "완료" 1건 확인.
- 진행 중 일감 설명에 "내일 오전 테스트 후 완료 처리 예정"을 덧붙이고 저장한다.
- 앱을 닫고 퇴근한다.

## 2. 결정 사항

1. **일감 생성 권한** — 일반 직원(담당자)도 새 일감을 직접 생성할 수 있는가, 아니면 팀 리드만 생성 권한을 갖는가?  
   **→ 누구나 생성 가능.** MVP에서는 로그인·역할 구분을 두지 않으므로 모든 팀원이 "새 일감" 버튼을 사용할 수 있다. 권한 분리는 이후 로드맵으로 이관한다.

2. **상태 변경 권한** — 담당자 본인만 자신의 일감 상태를 변경할 수 있는가, 아니면 모든 팀원이 타인의 일감 상태도 바꿀 수 있는가?  
   **→ 누구나 변경 가능.** 소규모 팀 신뢰 기반 운영을 전제로 권한 체크를 생략한다. 남용 방지는 운영 규칙으로 대응한다.

3. **신규 배정 알림** — 팀 리드가 새 일감을 배정했을 때 담당자에게 별도 알림이 가는가, 아니면 본인이 앱을 열어 직접 확인해야 하는가?  
   **→ MVP에서는 알림 없음.** 푸시·이메일 알림은 1일 개발 범위를 초과한다. 팀원은 출근 시 직접 앱을 열어 담당자 필터로 확인한다. 알림은 v2 기능으로 예약한다.

4. **일감 삭제 권한** — 일감을 삭제할 수 있는 사람은 생성자인가, 담당자인가, 팀 리드만인가, 아니면 누구나 삭제할 수 있는가?  
   **→ 누구나 삭제 가능, 단 confirm 다이얼로그 필수.** 역할 정보가 없으므로 권한 구분 불가. 실수 방지를 위해 삭제 전 "이 일감을 삭제하시겠습니까?" 확인창을 반드시 표시한다.

5. **동시 진행 상한(WIP limit)** — "진행 중" 상태로 유지할 수 있는 일감 수에 제한을 둘 것인가, 아니면 개수 제한 없이 동시에 여러 일감을 진행할 수 있는가?  
   **→ MVP에서는 제한 없음.** WIP limit 강제는 추가 UI 로직과 예외 처리가 필요하다. 운영 데이터를 쌓은 뒤 적정 상한을 결정하고 v2에서 도입한다.
