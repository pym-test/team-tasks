# team-tasks 페르소나

## MVP 헌장

| 항목 | 내용 |
|------|------|
| 데이터 모델 | 단일 테이블 (`Task`) — id, title, description, assignee, priority, status, dueDate, createdAt |
| 핵심 기능 | 일감 생성 · 수정 · 삭제 · 상태 변경 · 담당자/키워드 필터 (5개) |
| 목표 일정 | 1일 이내 코드 완성 |

---

## 페르소나

| 구분 | 역할 | 기술 수준 | 시나리오 1 | 시나리오 2 | 시나리오 3 |
|------|------|-----------|------------|------------|------------|
| **페르소나 A** | 팀 리드 (업무 배분 담당) | 중급 — 협업 툴 사용 경험 있음, 개발 지식 불필요 | 월요일 아침 스프린트 킥오프 때 이번 주 일감 5건을 팀원별로 생성하고 우선순위를 "높음"으로 지정한다 | 갑작스러운 요구사항 변경으로 담당자를 김철수→이영희로 재배정하고 마감일을 이틀 연장한다 | 금요일 오후 "담당자: 전체" 필터로 칸반 보드를 훑어보며 미완료 일감을 확인하고 팀에 공유한다 |
| **페르소나 B** | 개발자 (일감 실행자) | 초급~중급 — 칸반/이슈 트래커 첫 사용 | 아침 출근 후 본인 이름으로 필터링해 오늘 처리할 일감을 확인하고 "진행 중"으로 상태를 옮긴다 | 작업 중 요구사항이 추가되면 해당 일감의 설명(description)을 수정해 맥락을 업데이트한다 | 작업 완료 후 상태를 "완료"로 변경하고, 잘못 생성된 중복 일감을 삭제한다 |
| **페르소나 C** | PM (프로젝트 전체 조율) | 고급 — 다수 프로젝트 경험, 리포팅 중심 | 외부 이해관계자 미팅 전 키워드 검색으로 특정 기능 관련 일감을 빠르게 찾아 진행 현황을 파악한다 | 마감이 촉박한 일감의 우선순위를 "낮음"→"높음"으로 올리고 담당자를 재배정해 병목을 해소한다 | 스프린트 종료 시 "완료" 컬럼 일감 수를 헤더 요약 수치로 확인하고 완료율을 보고 자료에 기록한다 |
